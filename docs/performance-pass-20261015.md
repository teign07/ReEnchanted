# Loading and ink efficiency — 15 October 2026

The Reader requested faster loading and smoother ink, with existing features and experiences preserved. This pass makes five focused changes in the existing rendering and Radio paths.

- Temporary UIKit text/editor snapshots now use the same `AnimatableModifier` interpolation as live SwiftUI ink. The separate 30 Hz `TimelineView`, image-subtree reconstruction on its ticks, and settlement sleeper are removed. The snapshot still catches up to the original absolute arrival/submission time; its UIKit owner still restores the native control and releases the image at the existing deadline.
- Deterministic ink seed/timing values and the timing-image wrapper are prepared when the material modifier is created, rather than hashed and constructed in its interpolated body.
- A fully formed shader region returns the source pixel immediately. The previous final blend already returns that pixel at regional progress 1; noise for fibre/wander and both nine-sample pools cannot change it. Regions still gathering, absorption, pool samples, noise formulas, colours and timing are unchanged.
- Library-illumination prewarming consumes `ImageRenderer` output and its encoding on the main actor, while preview-file writing and display decoding run in utility workers. The preview decodes the exact JPEG bytes it has just written instead of reading the file back. The existing synchronous preview API remains available for other consumers, with the same file name/location, JPEG quality, render scale and output format. The folio publishes its finished picture after its pigment is ready, avoiding a new asynchronous window where a settled picture could appear before its animation data. Review of lazy SwiftUI exports refined this actor boundary in the scheduling pass below.
- A Radio world refresh reuses its one local source-input snapshot for grey, authored banter, runtime eligibility and Page context. It previously constructed the full source inputs four times. Page context now also receives the refresh's resolved world events instead of resolving them again. The authored resolver's own checks and receipt/lifecycle revalidation at playback time retain their existing paths.

No animation durations, sentence bands, eligibility, navigation, Keep payloads, reduced-motion/VoiceOver bypasses, image dimensions, cache budgets, source selection or audio playback were changed. No new persistent cache or alternate renderer was introduced.

## Follow-up: more redundant work removed

The Reader asked whether these are all gains without losses. The implementation preserves the intended features and artwork, but zero performance tradeoffs cannot be established from source inspection. In particular, native ink interpolation can draw more frames than the previous 30 Hz snapshot timer. Less CPU work per frame does not establish lower total GPU or battery cost; that remains a device measurement gate.

The follow-up removes four more sources of unnecessary work:

- Radio's recent-Page context now accumulates counts, sets and the newest Page's date/type in one archive pass. It no longer flattens/copies the archive, sorts recent Pages, then walks the sorted result several more times. The seven-day and future-date cutoffs, today's count, all tags/source IDs/type counts, and first-in-archive tie rule are retained. Weather, world-event and story-consequence tags still use their established paths.
- The archive shelf lazily flattens and filters each daily/weekly/monthly/annual category before sorting, avoiding four temporary copies of every kept Page. Every existing category, card, count and descending order remains.
- When assembling a new folio binding, document-cache lookups reuse the exact keys already constructed for the binding. Hash inputs, metadata ordering, pagination, cache sizes and invalidation remain unchanged. Independent prewarming still constructs its own key.
- Source-input assembly no longer assigns six fields twice or assigns a quill value that is subsequently replaced. The final assignments and authoritative decoding paths remain. No intervening computation used the removed values.

These changes add no cache, change no content-selection limit, and retain the existing drawing work and animation durations. They passed changed-file syntax parsing and diff checks. Source review checked date boundaries/ties, archive ordering, unchanged metadata-hash bodies, one-to-one document/key ordering, and the remaining final source-input assignments. They have not been built, benchmarked or exercised on device. The follow-up baseline and task-only patch are in `/private/tmp/reenchanted-efficiency-followup-20261015-847kqu6o/`.

## Desk, Explore Deeper, Keep and Rip It Out

The Reader clarified that steady response matters more than minimum load time: page turns, ink and taps should keep responding while the Book gathers its next material. This pass removes bursts of repeated synchronous work without shortening animations or changing what the Curator offers.

- Explore Deeper reuses one immutable binding snapshot within each synchronous request for signatures, exclusions and selection. - Photo-boundary preparation walks outward from the current leaf in linear distance order, preserving the lower-index tie break.
