# App Privacy Inventory

Last updated: 2026-06-19

Use this as the working inventory when filling App Store Connect's App Privacy
questionnaire. Re-check it before submission if network features, analytics,
sync, accounts, or server-side AI are added.

## High-level answers

- Third-party advertising: no
- Third-party analytics SDK: no known app runtime SDK
- Tracking across apps/websites: no
- Account creation: no
- Sign in required: no
- Data sold: no
- Data used for App Store ad attribution or third-party advertising: no

## Data that stays local by design

These data types are used by the app but should not be described as collected by
the developer unless a future feature transmits them off device:

- journal text, diary entries, moods, choices, prompts, and story fragments
- save data and archive/search state
- custom cast members, relationship context, places, and anchors
- HealthKit body signals read for Body Pages
- selected photos and generated illuminated artifacts
- calendar event context read by Calendar Doorway
- reminders/calendar events written on explicit user action
- local notification schedule
- Face ID / Touch ID / passcode authentication result

## Data that may leave the device in optional features

These are the places to be conservative in App Store Connect and the public
privacy policy.

| Feature | Data type | Destination | Purpose | Linked to user? | Tracking? |
| --- | --- | --- | --- | --- | --- |
| Weather Page / Weather seal | Approximate location coordinates | Weather provider endpoint | App functionality | No app account; may be visible to provider by IP | No |
| Anchor proximity / Location seal | Current location on device | Local app logic, unless paired with weather lookup | App functionality | No app account | No |
| USDA FoodData lookup | Food names typed by user, API key if configured | USDA FoodData Central | App functionality | No app account | No |
| Optional open web search | Search query typed or generated by user action | Search/web endpoint | App functionality | No app account | No |
| Optional Reddit app-only search | Search query and app-only token | Reddit API | App functionality | No Reddit user sign-in | No |
| Speech dictation | Spoken text/audio as handled by Apple speech services | Apple system service | App functionality | Governed by Apple system permission | No |

## Suggested App Store Connect privacy-label posture

This is a starting point, not a substitute for final review:

- Tracking: No.
- Data used to track you: none.
- Data linked to you: none unless a future account, analytics, or cloud sync
  feature is added.
- Data not linked to you: consider declaring coarse/precise location for
  weather if the weather endpoint receives coordinates; consider declaring
  user content/search history only for optional web/search lookups if those
  queries can include user-authored text.
- Health and fitness: the app reads HealthKit locally. If no HealthKit data is
  transmitted off device, this should be documented in review notes and the
  privacy policy, but may not need to appear as collected data.

## Review before submit

- Confirm whether Open-Meteo or any weather provider receives exact latitude and
  longitude or rounded coordinates.
- Confirm whether any local-brain helper sends prompts, photos, archive text, or
  generated context to a remote model in the App Store build.
- Confirm whether Reddit search is disabled when `RedditInstalledAppClientID`
  is empty.
- Confirm whether USDA lookup sends only parsed food names, not full private
  journal entries.
- Confirm no analytics SDK or crash reporting SDK has been added.
